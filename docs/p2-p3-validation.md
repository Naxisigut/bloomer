## 采集与提交

- 启动后立即采集，正常每 60 秒从 50 条重新开始。每轮只有一个实例，错过的 tick 不排队补发；超长轮次结束后重新安排未来一个周期。
- 客户端只请求已确认的 account-earnings 路径和 `limit` 参数；必须是 HTTPS，任何重定向均拒绝，令牌不会被转发。
- 每次请求重新读取仅当前用户可读的凭证文件。失败时只报告固定安全代码，不把令牌、上游消息、邮箱或原始响应写入日志。
- 响应体最多 2 MiB；每个窗口先按 ID 去重、排除过期，再相对轮前数据库计数。整个扩窗阶段不写明细，也不执行清理。
- 多窗口按 ID 合并，后取得的有效字段覆盖之前的字段。移动窗口的不同 ID 并集可以超过 1000，完整路径最多处理 1450 条次，不截断缓冲。
- 成功事务同时写入新增/确有修正的明细、最新官方快照、覆盖和成功时间；未变化的明细不执行 UPDATE。扩窗请求或 COMMIT 失败都不能前移成功检查点。
- 首次成功事务绑定账户，后续请求和启动配置都必须匹配；初次导入没有可查询明细时也保留官方快照和检查点。

## 恢复、限流和覆盖

最近完整成功时间不存在时读取 1000 条；已有历史但成功时间缺失时标记恢复。最近成功达到 1800 秒（包含相等边界）时直接读取 1000；关闭时间仅作辅助，不能掩盖关闭前的失败。强制退出没有关闭回调时依靠持久化的成功时间。

时钟比较使用 UTC 墙上时间。失败尝试保留时钟高水位，检测到未来检查点或回拨时采用恢复读取；若时间在请求中回拨，该轮失败。成功恢复建立新时间基准，之后正常轮次回到 50 条；旧的异常关闭时间不会永久强迫每轮恢复。调度每秒复查墙上时间，以识别跨休眠/时钟变化的计划偏差。

429 支持 `Retry-After` 秒数和 HTTP 日期。过大的秒数饱和到可保存的 UTC 年份上限，不允许溢出绕过等待；缺失或无效值等待 60 秒。截止时间保存到 SQLite，当前进程调度与重启后的第一轮都遵守。普通网络、认证和服务端失败留待下一正常周期，单轮内不无限重试。

首次导入即使 1000 条全新也只标记部分覆盖，不误报运行期间缺口。已有历史后窗口饱和，或恢复窗口没有保留范围内的已知 ID 重叠，记录疑似观测中断。相邻/重叠事件合并，相距不超过一个正常周期视为同一持续事件。后续成功不会抹去仍在保留范围内的缺口；周清理才裁剪过期区间。接口上限、重叠或无重叠都不是完整历史保证。

## 365 天范围与每周清理

时间统一到 UTC 微秒边界。采集固定本轮保留起点，`created_at < cutoff` 的记录先排除，不重新导入，也不参与扩窗。恰好等于截止时间的记录保留。

存储层的流式明细读取与合计共享 365 天范围，物理清理前就排除过期数据。显式更早范围返回截断标记及可用起点。官方累计和余额保持官方口径。正式明细分页、模型筛选、按时区统计和 HTTP 响应在 P4 实现。

启动时安排清理检查；距上次成功满 7 天补做一次，不重放每个错过的周。任务将 cutoff 持久化，每批最多 1000 条，短事务之间让到期采集先执行。中途失败保留已提交批次，不推进成功时间，至少间隔 60 秒后重试；重启继续同一冻结任务。时钟回拨只能收窄删除范围。

最后一批完成后重新计算历史起点、删除/裁剪过期缺口，再推进成功清理时间。每周任务不执行 VACUUM；删除后数据库主文件不立即缩小不视为失败。

## 健康与生命周期

`GET /v1/health` 保持独立 Bearer 认证，报告采集状态、最近尝试与成功、恢复原因、限流截止、数据过期、可见覆盖/缺口数量和清理状态。读取时间和保留期固定一次，成功检查点与可见覆盖来自同一个 SQLite 只读快照。运行期间写入故障还能通过内存状态呈现；数据库查询本身不可用时明确 503。

默认 `collection_enabled=true`。官方凭证不可用时进程仍运行、每周期重试，并报告降级。设置为 false 可停止采集，清理仍运行。退出先取消任务并等待事务提交/回滚，再保存正常关闭时间并关闭接口、数据库及锁。

## 验证与证据

Go 测试使用本机 HTTPS 模拟服务、可控时间和真实临时 SQLite，所有凭证与收益均为合成值。集成测试贯通真实 TLS 客户端、JSON 解码、首次导入、扩窗和 SQLite 成功事务，验证请求顺序 1000→50→100→300。主要验证场景：

| 分类 | 已覆盖边界 |
| --- | --- |
| 客户端 | 请求路径/参数/认证，凭证轮转，401/403/429/503，重定向不转发，畸形/过大响应，响应头与响应体超时，取消 |
| 扩窗 | 50 全新后 100 仍全新继续 300；100 中只有 70 新停止；下一轮恢复 50；跨窗口并集 1450 不截断 |
| 数据 | 正常 8 新记录、字段修正、未变化不 UPDATE；同响应重复折叠与冲突失败；后一次修正覆盖；过期先过滤 |
| 事务 | 第 2 次请求失败；使用延迟外键触发真实 COMMIT 失败，验证全部回滚且后续事务可恢复 |
| 恢复 | 首次导入、29:59 / 30:00、失败 25 分再停机 10 分、未来检查点、失败后回拨、请求期间回拨、恢复后返回 50 |
| 覆盖 | 首次 1000 全新不报缺口，恢复无重叠报缺口，之后成功不清除，连续事件合并 |
| 限流 | 秒数/日期/无效/过大 Retry-After，截止前不请求，关闭数据库后重开仍等待，恰好截止允许采集 |
| 调度 | 超长轮次/模拟休眠不排队，清理批次之间到期采集优先，限流跨 tick，墙上时钟回拨重新判断 |
| 互斥 | 采集网络阶段清理无法进入，取消后正常释放协调器 |
| 留存 | 365 天相等边界、过期未物理删除时明细与合计已过滤、早期请求范围截断、官方累计保持 |
