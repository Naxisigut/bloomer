# Agent 数据库、迁移与恢复

P1 数据库 schema 为 **1**，SQL 位于 `apps/agent/migrations/001_initial.sql`，编译时嵌入程序。数据库默认位于用户应用数据目录，不进入仓库。

## 表和连接

- `earnings`：`(account_id, record_id)` 主键，保留来源文本 ID；时间与模型查询各有组合索引。金额为有符号 int64 微美元，时间为 UTC 整数微秒。
- `account_summary_current`：每个账户仅保留最新官方汇总，不每分钟永久追加快照。
- `sync_state`：最近尝试、完整成功、错误分类、同步模式、覆盖状态与上次写入计数。
- `coverage_gaps`：观测中断及疑似缺口，带账户和时间索引；不等同于精确丢失收益边界。
- `maintenance_state`：单行启动、正常关闭、清理成功和限流截止时间。
- `schema_migrations`：版本、文件名、SHA-256 与迁移时间；与 `PRAGMA user_version` 共同检查。

SQLite 使用 WAL、FULL 同步、5000 ms 忙等待和外键检查。写连接最多 1 个，只读池最多 2 个；配置通过 DSN 应用于每个连接。只读连接使用 `mode=ro` 和 `query_only=1`。所有写操作经存储模块的串行事务入口；P2/P3 再加入采集/清理协调器。

P1 定义表结构和事务边界，尚不写入收益或推进采集成功检查点。网络请求不得放在写事务内。数据库不可用时返回明确错误，不能将错误转换为 0 收益。

## 迁移

1. 服务获取数据目录的 OS 文件锁。
2. 检查 `user_version`、迁移历史与已应用文件的校验和。
3. 新建空库直接初始化；不接管未版本化的非空库。高于当前程序支持的 schema 拒绝启动。
4. 已有版本升级前，通过 `VACUUM INTO` 创建包含已提交 WAL 数据的一致性副本；文件名为 `agent.db.pre-v<目标版本>-<纳秒时间>.bak`。
5. 每个 SQL 文件在短事务内执行；SQL、迁移历史和版本号一起提交。失败时整份文件回滚并停止启动，已完成的较早版本仍保持有效。

已应用的迁移文件不可修改；新增结构使用下一个连续编号。P1 的“可回滚”指**失败迁移的事务回滚**与一致备份恢复，不提供破坏性在线 down migration。测试覆盖初次失败无残留、旧版升级失败、DDL 回滚、重新升级、高版本拒绝和校验和冲突。

## 一致备份与恢复

存储模块已提供经写锁协调的 `VACUUM INTO` 备份能力，并验证主库/WAL 中的数据和维护检查点恢复一致；P1 尚未开放备份 CLI。升级会自动调用该能力。不要在服务写入时只复制 `.db` 主文件。

需要恢复数据库时：

1. 正常停止 Agent 并确认进程已退出；尚未安装 launchd 时，使用终端 Ctrl+C 或 SIGTERM。
2. 将现有 `.db`、`-wal`、`-shm` 作为同一组保存在单独故障排查目录。
3. 将一致性备份复制为配置指定的 `agent.db`，不要混入旧 WAL/SHM。
4. 保持数据目录 0700、数据库 0600，使用支持该 schema 的程序重新启动，核对健康与检查点。
5. 验证升级成功后按需移走或删除升级前临时备份；P1 不自动删除恢复保障文件，也不默认周期备份。

启动、停止和迁移的日志可用于核验。正常退出记录失败时程序报告错误；强制退出不会伪造正常关闭时间。恢复同步判断和收益物理清理在 P3 实现，不因表已存在而视为完成。
