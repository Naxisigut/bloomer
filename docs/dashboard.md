# 静态看板架构

更新日期：2026-10-23

独立项目位于 `apps/dashboard`，启动方式与完整说明见[看板 README](../apps/dashboard/README.md)。

## 产品范围

提供五个页面：首页、收益分析、全网数据、我的设备、告警记录。所有页面固定使用中国标准时间（Asia/Shanghai，UTC+8），不提供时区切换，也不读取旧的时区偏好。桌面使用侧栏与整行趋势图，窄屏使用顶部导航并调整指标排列。

初次没有设备时进入明确标注的演示模式；有已保存设备时恢复上次选择，首次优先选真实设备。设备失联时保留真实模式并显示错误，不用演示数据掩盖问题。

首页右侧设备卡片包含设备切换、工作状态、当前运行模型、温度、内存、近 1 小时收益、近 24 小时收益和可用余额，仅在首页显示。当前运行模型取自本机设备状态的 `current_model`。设备名称旁以绿色/红色圆点表示采集正常/异常，悬停可查看具体状态。1 / 24 小时采用独立的滚动窗口，汇总所选设备全部模型，不受下方日期或模型筛选影响；展示 4 位小数，不展示可提现金额。今日收益在左侧，最新 50 条明细紧挨在收益图下方。侧栏顶部显示 Bloomer；顶栏日期与刷新仅在首页与「我的设备」显示。

首页左侧展示固定当天的按小时收益折线图；日期固定为北京时间当天，不提供日期或粒度筛选。默认显示全部收益，可同时选择多个模型，并可叠加全部收益曲线；今日总收益始终统计全部模型，避免多选时重复相加。首页模型选择、查询结果和在途请求独立于其他菜单，切换设备重置选择，每分钟、手动刷新及返回首页时查询当天；跨午夜清除前一天的图表，查询成功后，已过去及当前小时没有收益时显示 0 值点，未来小时保持空白；查询失败继续提示错误，不补为零。曲线使用单调三次插值平滑连接，不产生额外的峰值或低于零的收益；横轴逐小时显示 00:00～23:00，窄屏横向滚动。

首页在当天收益图下方显示所选设备最新 50 条收益明细，不提供筛选或翻页，随首页刷新更新。打开旧的 `#records` 地址会回到首页。首页与「我的设备」顶栏保留日期与刷新；收益分析、全网数据、告警记录不显示顶栏大标题、日期与刷新，各页使用面板内操作。

「收益分析」使用独立 `#analysis` 页面：筛选栏含设备、时间（今天 / 昨天 / 近 7·30·90 天 / 近一年 / 自选日期）、粒度（按小时 / 天 / 月，不合法项禁用；默认 ≤2 天按小时、≤90 天按天、否则按月）和多选模型标签（最多 8 个，「全部模型」互斥；列表来自上次结果的 `models`）。首次进入且从未查询时，以当前设备、近 7 天、全部模型自动查询一次；之后仅在点击「查询」时请求，切换菜单返回保留条件与结果。查询可取消，新查询中止旧查询，失败保留上次结果。图表区含指标卡、ECharts 趋势 / 累计 / 占比 / 任务与均值 / 24 小时分布 / 星期×小时与模型×小时热力图、模型对比；无数据时空状态，不画假零。分析页不参与自动刷新，只统计所选设备本机收益（`GET /v1/earnings/analysis`）。「查询」旁的「导出明细」按当前设备、时间范围和模型筛选，通过 `GET /v1/earnings` 分页下载 CSV；粒度不影响导出。开发依赖 `echarts`，通过 `pnpm run vendor` 复制 ESM 产物到 `public/vendor/` 并由静态服务器直接提供。

装饰性按钮 / 指标图标、明细字母头像及重复状态列已移除；窄屏导航和有数据含义的图例、状态指示保留。

我的设备展示 Agent 保存的最新设备状态与采集时间，包括 CPU、内存、Swap、GPU、温度与热压力、磁盘、进程和模型等指标。演示设备返回合成的最新样本。

我的设备还提供[远程操作](remote-control.md)：本地模型多选切换与开启、官方目录模型下载、Darkbloom 关闭和重启。操作前确认目标，后台执行并展示最近 50 条结果；旧 Agent 提示升级，演示设备只读。

「全网数据」独立展示对照组模型收益估算、推荐、自动切换开关与最近切换记录；按设备查看，演示设备只读。需 Agent 支持 `/v1/device/network-rates`。首页设备卡片显示本机当前运行模型，不显示全网推荐。

## 实现选择

- 普通静态服务器提供原生 HTML / CSS / JavaScript；无 Node 运行时服务与打包步骤。收益分析页使用 vendored ECharts（`pnpm add -D echarts` + `pnpm run vendor`），浏览器以 ES module 直接加载。
- 每分钟及页面从后台返回前台时，按当前菜单刷新设备状态、收益及采集健康；连接、确认和导出期间暂停自动刷新。首页刷新同时更新最新 50 条明细。设备状态请求期间保留现有显示，响应完成后再判断新样本是否过期，避免旧缓存重绘造成短暂的过期提示。
- 浏览器按所选设备地址携带 Bloomer Bearer 令牌直连既有 `/v1` 查询与控制接口。任务活动和设备收益仍由 schema 5 采集端保存，查询不触发采集。
- 连接统一手动添加或导入，浏览器不读取本机 Agent 文件；远程设备使用已有 Tailscale HTTPS 地址及端口。
- 名称、地址、Bloomer access.token 与选中设备持久保存在浏览器该来源的 localStorage；测试健康成功后才保存。官方 Darkbloom 令牌仅由 Agent 读取；不进入网页、仓库或浏览器。来源隔离和迁移方式见[连接设备指南](connect-device.md)。
- Agent 1.0.7 起允许任意网页来源（`Access-Control-Allow-Origin: *`），无需来源配置。合法 OPTIONS 免令牌，实际 GET/POST 必须认证。预检显式允许 Authorization、Content-Type 和 Accept，合法预检响应缓存 2 小时（`Access-Control-Max-Age: 7200`），不启用跨域 Cookie 凭证，浏览器使用 `credentials: omit`；成功与错误响应都带 CORS 头，原无 Origin 调用不变。
- 请求层保留参数白名单、12 秒超时、取消、8 MB 上限、响应校验及中文错误映射；浏览器不能可靠区分网络/证书/CORS 时给联合排查提示。
- 演示生成和游标均在浏览器执行，保留只读限制；控制确认、幂等编号、失败后核对和后台任务规则不变。
- 每台设备单独切换查询，首版不做跨设备收益合并，避免同一账户重复统计。
- 首页使用独立的当天按小时统计和当天模型列表，选中模型分别请求同一时间边界的小时统计，按模型显示多条折线。所有曲线共用 Y 轴，按所选数据范围生成 1 / 2 / 5 × 10ⁿ 的规整金额间隔；刻度以整数微美元生成，文字精度跟随间隔，网格线与标注金额一致，小额收益最多显示 6 位小数。悬停或键盘聚焦数据点时，标签仅显示 4 位小数金额，背景和边框与对应曲线同色；时间与模型仍保留在数据点的无障碍描述中。
- 金额以整数微美元计算；统计时区固定以 IANA 名称 Asia/Shanghai 传给 Agent，日期范围遵循中国标准时间日历并转换为 UTC 半开区间。
- CSV 按收益分析页当前筛选读取全部分页，防重复记录和公式注入；金额精确到 6 位小数。选定多个模型时按模型分别请求后合并。导出时间与页面统一使用北京时间（UTC+8），保留来源小数秒精度并标注 `+08:00`，文件名使用北京时间的筛选开始日期。最多 100,000 条；超限时提示缩小时间范围，不下载截断文件。切换设备会取消进行中的导出。

## 状态处理

界面分别处理未完成首次采集、连接失败、凭证无效、数据库暂不可用、数据过期、采集关闭、限流等待、历史缺口、查询范围被保留期截断以及清理失败。`/v1/health` 的 `server_time` 为 Agent 当前 UTC 时间，看板用于校正浏览器时钟偏差；`next_collection_at` 为下一次计划收益采集开始时刻（限流时为实际重试时间），采集关闭或未排程时为 null。

首页设备卡片与「我的设备」运行状态中的「工作状态」只显示本机任务标志：处理中、排队或无任务。进程未运行、任务标志缺失分别显示未运行、未知。看板不因样本采集时间将工作状态标为过期，始终展示最近一次样本中的任务结论。看板不展示 CPU/GPU 摄氏温度；运行状态保留系统热压力等指标。Agent 后台仍会结合收益计算 `is_idle` 供告警等逻辑使用，但看板不再展示该字段。设备卡片同时展示本机设备热压力与内存压力，正常为绿色、轻度热压力/内存压力偏高为橙色、较高或严重热压力/严重内存压力为红色。详情与历史保留任务标志、设备收益时间和同步时间。无需网页登录令牌。

余额来自官方账户快照，不受本地留存期限制。本期、近 1 / 24 小时收益和趋势来自所选设备保存的明细；初次导入只能取得最近窗口，空白分组不代表官方零收益。

## 验证与边界

当前变更以本地合成数据验证 CORS、令牌、连接存储、查询、分页、CSV 和模拟控制流程。家中真实 Tailscale HTTPS 联调需更新 Agent后由用户完成，不能将历史真实设备验证视为本次直连架构的生产验证。

本期不增加账号、配对码、会话签发、令牌刷新或中心服务。普通静态托管即可；静态服务器不存储连接信息。运行环境原数据库、历史、Agent 配置及令牌保留。本次不部署远程设备，不执行真实 Darkbloom 控制操作。
