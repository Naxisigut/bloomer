# Bloomer Dashboard

原生 HTML / CSS / JavaScript 静态看板；无框架、打包步骤和 Node 运行时服务。普通静态服务器只提供 `public/` 文件，浏览器直接请求所选 Agent。

在仓库根目录启动，例如：

```sh
python3 -m http.server 18080 --bind 127.0.0.1 --directory apps/dashboard/public
```

打开 <http://127.0.0.1:18080> 并固定使用此来源。也可使用任意等价静态托管；禁止以双击 `file://` 页面作为正式方式。修改文件后刷新浏览器即可。

首次使用请阅读[完整连接设备指南](../../docs/connect-device.md)：家中设备升级 Agent、取得带端口的 Tailscale HTTPS 地址、读取设备端 Bloomer 令牌、测试并保存。Agent 1.0.7 起允许任意网页来源，无需配置来源。

## 第一版功能

所有页面的日期、时间显示与查询固定使用中国标准时间（Asia/Shanghai，UTC+8），不再读取此前保存的时区偏好。

- 首页设备卡片：右侧列出设备切换、工作状态、当前运行模型、温度、内存、近 1 小时收益、近 24 小时收益、可用余额。卡片仅在首页显示；当前运行模型来自本机设备状态的 `current_model`，与「我的设备」运行状态为同一次读取，无模型或读取失败时显示「—」或状态原因。工作状态只根据本机任务标志显示处理中、排队或无任务；热压力与内存压力来自本机。Agent 版本与三路采集状态显示在「我的设备」运行状态的 Agent 状态分组中。近 1 / 24 小时收益汇总所选设备全部模型，不受下方日期或模型筛选影响，金额展示 4 位小数；不展示可提现金额。
- 首页当天收益：固定展示北京时间当天的按小时收益折线图，无日期或粒度筛选；默认显示全部收益，可同时勾选多个模型，全部收益也可与模型曲线叠加。显示独立的今日总收益，每 60 秒和手动刷新时更新；跨午夜重新查询当天，已过去及当前小时无收益时显示 0 值数据点，未来小时保持空白。折线平滑连接且不超出相邻数据值，横轴覆盖 00:00～23:00，每小时一个数据点，宽度不足时刻度标签改为每 2 小时一个；极窄屏可横向滚动。查询失败时提示错误，不将失败当作零收益。模型选择与收益分析互不影响。
- 首页最新明细：紧挨在左侧今日收益图下方，显示所选设备最新 50 条收益记录，不提供筛选或翻页，随首页刷新更新。旧的 `#records` 地址会回到首页。
- 收益分析：独立 `#analysis` 页面，点击「查询」后调用 `GET /v1/earnings/analysis`（演示设备走 `demo.js`）。筛选含设备、今天 / 昨天 / 近 7·30·90 天 / 近一年 / 自选日期、粒度（hour 仅跨度 ≤31 天；默认 ≤2 天 hour、≤90 天 day、否则 month）及最多 8 个模型标签。首次进入自动以当前设备、近 7 天查询一次；之后手动查询，页面不自动刷新。ECharts 图表覆盖趋势、累计、占比、任务与单笔均值、24 小时分布、热力图与模型对比；金额用整数微美元计算。安装依赖后执行 `pnpm run vendor` 更新 `public/vendor/echarts.esm.min.mjs`。
- CSV 导出：在收益分析页「查询」旁边。按当前设备、时间范围和模型筛选导出全部明细分页；粒度不影响导出。选定多个模型时按模型分别请求后合并。金额保留 6 位小数，时间与页面统一为北京时间（UTC+8），保留来源小数秒精度并明确标注 `+08:00`；文件名使用北京时间的筛选开始日期。最多 100,000 条；超限时提示缩小时间范围，不下载截断文件。切换设备会取消进行中的导出。
- 设备管理：测试并保存连接、切换、移除。运行状态的 Agent 状态分组分别展示收益采集、运行状态采集与全网数据采集；配置关闭的一路显示已关闭，参与的一路超出新鲜窗口显示异常。限流、清理和历史缺口仍由页面提示说明。
- 远程操作：在“我的设备”选择目标设备，支持多模型切换、官方目录下载、Darkbloom 开启 / 关闭 / 重启；确认后后台执行并显示最近操作。需升级设备端 Agent；演示设备不执行。详见[远程操作说明](../../docs/remote-control.md)。
- 全网数据：独立菜单页，展示所选设备的对照组统计估算、自动切换开关（需确认）、候选表、近 24 小时总输出 token 平滑折线与最近切换记录；演示设备只读。需 Agent 支持 `/v1/device/network-rates` 接口，趋势图另需 `/v1/device/network-rates/token-trend`。首页设备卡片显示当前运行模型，不显示全网推荐。
- 设备实时详情：CPU / 进程 CPU、内存与压力、Swap、GPU、系统热压力、磁盘余量、进程、当前模型与本地就绪、与首页设备卡片一致的工作状态和固定硬件信息，标明采集时间。
- 数据查询：独立设备状态明细菜单，支持设备、精确到分钟的起止时间、每页 25～500 条、前后翻页及单条完整详情；默认近 24 小时，提供近 7 天快捷范围。查询区间与收益筛选独立，缺失时间段不补零；没有总条数接口，因此不虚构总页数。
- 首页自动刷新在每次刷新完成后链式调度：优先对齐 Agent 返回的下一次采集时间（约 +8 秒，15～90 秒区间），旧 Agent 无字段时回退 60 秒；连续失败时退避至 120 秒、300 秒并在顶栏提示下次重试。页面从后台返回前台时立即刷新并重置计时。页面隐藏、正在连接或导出时暂停相应刷新。首页刷新同时更新最新 50 条明细。首页 overview 仅检查当前选中设备 health，「我的设备」仍检查全部设备。设备状态请求完成后更新显示；读取失败时仍显示错误提示。
- 演示模式：合成的 90 天历史，明确标注，独立于真实设备。连接失败不会改用演示收益。
- 设备状态演示返回合成的最新样本，沿用明确的演示标识；包含处理中、排队、无任务和未运行演示场景。

## 设备状态口径

浏览器携带 Bloomer Bearer 令牌直接读取 Agent `GET /v1/device/state`，不触发采集。首页设备卡片与「我的设备」每 60 秒刷新最新样本。

首页设备卡片与运行状态详情中的「工作状态」口径一致，只读取样本中的 `inference_active` 与 `request_work_pending`：正在处理为「处理中」，仅有排队为「排队」，两者都为否为「无任务」。Darkbloom 未运行显示「未运行」，任务标志缺失或无效显示「未知」。看板不因样本采集时间或 `meta.data_stale` 将工作状态标为过期，始终展示最近一次样本中的任务结论。设备卡片「温度」「内存」分别展示系统热压力与内存压力，直接从 macOS 采集；不展示 CPU/GPU 摄氏温度。Agent 仍会在后台计算基于收益的 `is_idle` 供告警等逻辑使用，但看板不再展示该字段。旧 Agent 的任务字段保持未知，收益功能独立运行；完整规则见[设备状态采集](../../docs/device-state.md)。


## 连接设备与存储

在「我的设备」页点击列表末尾 **+**，填写名称、Agent 地址和 **Bloomer access.token**，测试成功后保存。地址例如 `https://device.your-tailnet.ts.net:8443`，包含实际 HTTPS 端口，不附加 `/v1`；本机测试可用 `http://127.0.0.1:17890`。远程地址只接受 Tailscale `.ts.net` HTTPS。测试与保存都直接请求 Agent `/v1/health`。

必须在**运行 Agent 的设备端终端**，使用安装和运行 Agent 的**同一 macOS 用户**获取令牌：

```sh
cat "$HOME/Library/Application Support/Bloomer/agent/access.token"
```

自定义 `access_token_file` 时使用实际路径。它不是 `~/.darkbloom/auth_token`；只填写到自己的看板，不提交仓库或粘贴到聊天。

浏览器 localStorage 持久保存名称、地址、令牌和所选设备。切换浏览器、主机名、协议或端口，或清除网站数据后需重新添加。在首页或导航中的 **添加设备** 连接新设备。移除只删除浏览器连接和待核对请求记录，设备数据不变。令牌更换后移除旧连接重新添加。

## 数据与访问边界

静态服务器 → 浏览器下载 HTML/CSS/JS；浏览器 → Tailscale HTTPS → Agent `/v1`，每次实际请求携带 `Authorization: Bearer <access.token>`。Agent 负责采集、SQLite 存储、查询、统计及远程操作。静态托管方不需要令牌，但必须信任其所提供的网页代码。

Agent 返回 `Access-Control-Allow-Origin: *`，允许任意网页来源；合法 GET/POST 预检免认证，实际请求仍校验 Bloomer Bearer 令牌。预检显式允许 Authorization、Content-Type 和 Accept，不启用 Cookie 跨域凭证；浏览器继续使用 `credentials: omit`。成功及错误响应都带 CORS 头，无 Origin 的 CLI 调用兼容。无需在设备端配置网页来源。升级和网络/证书/CORS/401 排查见[连接指南](../../docs/connect-device.md)。

请求层设 12 秒超时，支持调用方取消、最大 8 MB 响应、契约基本格式校验、重定向拒绝和固定中文错误；不输出令牌或设备原始错误。浏览器不能区分的网络、证书和 CORS 异常只给联合排查提示。演示数据在浏览器本地生成，控制请求在 UI 和请求层都被禁止。

远程控制沿用二次确认、后台状态、原请求编号幂等重试及失败后结果核对；控制开启时同一 Bloomer 令牌也授予操作权限，可在家中配置 `remote_control_enabled: false` 禁用。不引入账号、配对或会话服务。

金额在计算、排序、显示和导出中使用 `BigInt` 保留整数微美元；只有图表几何位置转换为浮点数。官方累计 / 余额与本地已保存收益是不同口径。同一账户的多台设备切换查看，不相加，也不将 Provider 身份推断为物理设备收益。

首次导入窗口、365 天留存、疑似历史缺口都会影响本地统计。数据过期、限流、采集关闭、数据库无数据、连接失败分别显示，不把无数据当作零收益。

首页最新 50 条随设备切换和首页刷新更新，不受当天收益图的模型勾选影响。收益分析页的「导出明细」使用该页当前的设备、时间范围和模型筛选；切换菜单会保留分析条件。导出进行中会暂停自动刷新，切换设备会取消本次导出。

界面只保留窄屏导航图标、实际状态指示和图表图例；指标卡、按钮、设备卡与明细行的装饰图标，以及重复的“已记录”列已移除。

## 开发验证

Node.js 22+ 仅用于开发检查和测试；运行网页不需要它。以下命令在 `apps/dashboard` 执行：

```sh
npm run check
npm test
```

测试覆盖浏览器直连 GET/POST、鉴权、错误净化、超时/取消/大小及格式检查、连接测试后持久化、恢复选择、导入与存储失败、演示只读，以及既有金额精度、日期、CSV、分页和状态规则。回环模拟测试需允许本机监听。

浏览器复验：保持普通静态服务器运行，另开终端在 `apps/dashboard` 执行 `node dev/mock-agent.mjs`。使用 `http://127.0.0.1:18190` 和 `:18191`，合成测试令牌为 `bloomer-mock-only`（仅用于此模拟服务）。可复验连接与刷新恢复、设备切换、日期和模型筛选、分页、CSV、演示只读及模拟控制结果核对。该模拟器只返回合成数据，不访问真实 Agent、数据库或 Darkbloom。Node 模拟服务是测试工具，不属于看板运行时。

## 告警记录

“告警记录”页按设备显示最近 10 条告警与恢复、推送结果、重试次数和下次重试时间；可发送一条 Bark 测试推送。真实发送由设备端 Agent 执行，浏览器不持有 Bark Key。演示设备只读；旧 Agent 提示升级。配置见 [告警说明](../../docs/alert.md)。
